# Ролик и снимки

Промо-ролик и проверочные снимки собираются кодом из настоящего приложения:
никакого монтажа руками, поэтому после правки дизайна ролик пересобирается
одной командой.

| Файл | Что делает |
|---|---|
| `stage.html` | Сцена 1920×1080: заставка, подписи, камера, курсор. Внутри — приложение во фреймах. **Сценарий — функция `main()` в конце файла** |
| `shim.js` | Виртуальное время во всех фреймах: `performance.now`, `Date`, таймеры, `requestAnimationFrame` и CSS-анимации идут только тогда, когда запись сдвигает их на кадр |
| `record.js` | Пишет кадры в `out/frames/` и события кликов и набора в `out/events.json` |
| `audio.py` | Звук по событиям: подложка, щелчки на клики, тики на набор, финальный звон |
| `render.js` | Всё подряд: кадры → звук → `out/utmka-promo.mp4` |
| `demo.js` | Демо-данные и подмена `/api` веба: вошёл, есть история, шаблоны, справочник, помощник |
| `shots-web.js` | Снимки веба во всех разделах и оформлениях |
| `shots-desktop.js`, `flow-desktop.js` | Снимки фронта десктопа и проход по генератору в окне 1180×820 |
| `tauri-mock.js` | Поддельный мост Tauri для фронта десктопа в обычном Chromium |

Всё, что получается на выходе, падает в `out/` — в git и в образ веба эта
папка не едет.

## Что нужно один раз

- Node 20+ и Playwright глобально: `npm i -g playwright`, потом
  `npx playwright install chromium`. В зависимости воркспейсов Playwright
  специально не добавлен — общий лок и Docker-сборка веба о нём не знают;
- `ffmpeg` в `PATH`;
- Python 3 с numpy: `pip install numpy`.

## Ролик

```bash
# 1. Веб в продакшен-режиме на :3000 (дев-сервер с его оверлеем и HMR в кадр не годится)
cd apps/web && npx next build && npx next start -p 3000

# 2. В другом терминале, из корня репозитория
node scripts/promo/render.js
```

Запись идёт несколько минут: каждый кадр — честный скриншот. Для быстрой
проверки начала сценария хватит `MAXF=90` (три секунды):
`MAXF=90 node scripts/promo/render.js` (в PowerShell — `$env:MAXF=90` перед запуском).

Переменные: `BASE` (адрес веба, по умолчанию `http://localhost:3000`),
`FPS` (30), `MAXF` (предел кадров, 1500), `OUT` (папка вывода),
`PYTHON` (`python3`, на Windows `python`).

### Как править сценарий

Сценарий — `main()` в `stage.html`, обычный `async`-код в виртуальном времени:
`await wait(мс)` — пауза, `caption(html, ярлык)` — подпись,
`focus(x, y, масштаб, …)` и `cam(…)` — камера, `clickOn(селектор)` и
`type(текст, мс на знак)` — курсор и клавиатура. Селекторы ищутся в окне `#f1`.

Грабли, на которые уже наступили:

- **Клик во время движения камеры промахивается.** `clickOn` пересчитывает
  цель после подлёта, но после `cam()` или `focus()` всё равно ставь паузу
  не короче длительности движения;
- **Кнопка за краем прокрутки не нажимается.** `clickOn` сам подкатывает
  её (`reveal`), но если элемент ищется руками — прокрути его в зону видимости;
- **Курсор и кольцо клика — `pointer-events: none`.** Иначе настоящий клик
  Playwright приходит в нарисованный курсор, а не в кнопку;
- `window.__start()` нельзя ждать из `page.evaluate`: сценарий закончится
  только тогда, когда его прокрутят кадры, и запись повиснет.

## Снимки

Веб — тот же `next start -p 3000`, потом `node scripts/promo/shots-web.js`.

Десктоп:

```bash
cd apps/desktop && npx vite build && npx vite preview --port 1421 --strictPort
node scripts/promo/shots-desktop.js      # окно 1180×820 во всех видах + край у 900 px
node scripts/promo/flow-desktop.js       # шаг 3, подстановки, готовая ссылка, правка
```

Мост Tauri здесь поддельный, поэтому это проверка вёрстки, а не окна:
сохранение файлов, сеть и база не настоящие. Живое окно — `npx tauri dev`.

Свой набор снимков задаётся JSON в `SHOTS`, например
`SHOTS='[{"name":"x","w":1440,"h":900,"path":"/batch","theme":"light","skin":"dots"}]'`.
Пустой `skin` — «ПРОНИН-ОС». У десктопа `prep` — JS-выражение, оно
выполняется на странице перед снимком.
