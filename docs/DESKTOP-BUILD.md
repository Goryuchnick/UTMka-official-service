# UTMka 3.0 — сборка и выпуск десктопа

> Что делать руками, чтобы из репозитория получился установщик у пользователя.
> Инженерные решения — в [ARCHITECTURE.md](ARCHITECTURE.md) §11, план работ —
> в [DESKTOP-PLAN.md](DESKTOP-PLAN.md).

---

## 1. Что нужно на машине

| Компонент | Как проверить | Если нет |
|---|---|---|
| Rust `stable-msvc` | `rustc -V` → 1.97+ | `winget install Rustlang.Rustup`, затем `rustup default stable-x86_64-pc-windows-msvc` |
| MSVC Build Tools | сборка не падает на `link.exe` | VS Build Tools с рабочей нагрузкой C++ |
| WebView2 | есть в Windows 10 1803+ и 11 | ставится установщиком приложения |
| Node 20+ | `node -v` | — |

⚠️ **GNU-тулчейн Tauri не подойдёт** — классическая ошибка `linker 'link.exe'
not found` растёт отсюда. Если `link.exe` не находится и при MSVC, собирать из
«x64 Native Tools Command Prompt for VS 2022».

### Переменные окружения (заданы на машине владельца)

```
CARGO_HOME       = D:\rust\cargo
RUSTUP_HOME      = D:\rust\rustup
CARGO_TARGET_DIR = D:\rust\target\utmka
```

`target/` у Tauri в debug разрастается до десятков гигабайт — держать его на
системном диске не стоит. Полезно раз в месяц: `cargo clean`.

Исключения Defender на `CARGO_HOME` и `CARGO_TARGET_DIR` **не поставлены**
(нужен админ). Это только скорость: холодная сборка из ~2 минут может
растянуться до 10–15. Ставятся так, из консоли администратора:

```powershell
Add-MpPreference -ExclusionPath "D:\rust\cargo", "D:\rust\target"
```

## 2. Разработка

```bash
cd apps/desktop
npx tauri dev
```

Открывается окно, Vite слушает 1420. Правки экранов и стилей подхватываются
на лету, правки Rust — пересборкой (несколько секунд).

🪤 **Если `tauri dev` падает с «Port 1420 is already in use»** — на Windows
Tauri не всегда закрывает дочерний Node чисто, и сирота держит порт. Лечится:

```powershell
Get-NetTCPConnection -LocalPort 1420 -State Listen |
  ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

🪤 **«database is locked» на старте** означает, что рядом живёт второй экземпляр
приложения (обычно не закрытое окно от прошлого запуска). Один файл базы — один
процесс.

## 3. Сборка установщика локально

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY = Get-Content <путь к приватному ключу> -Raw
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = ""
cd apps/desktop
npx tauri build
```

Результат — `D:\rust\target\utmka\release\bundle\nsis\UTMka 3.0_3.0.0_x64-setup.exe`
и рядом `.sig` для апдейтера.

Ключ подписи нужен даже локально: `createUpdaterArtifacts: true`, а подпись
апдейтера у Tauri **обязательна и отключить её нельзя**.

🪤 **Ключ передавать без хвостового перевода строки.** `Get-Content -Raw` в
PowerShell добавляет `\n` в конец, и Tauri молча собирает установщик **без**
`.sig` — сборка при этом успешна, а обновления потом не работают. Надёжный
способ — bash: `export TAURI_SIGNING_PRIVATE_KEY="$(cat <файл>)"`. После сборки
проверять, что `.sig` появился рядом с `.exe`.

🪤 **Папка установки берётся из `productName`.** Поэтому он «UTMka 3.0», а не
«UTMka»: NSIS ставит в `%LOCALAPPDATA%\{productName}` и **вычищает эту папку**
при установке. Каталог `UTMka` занят версией 2.2 — с прежним именем установщик
3.0 сносил её вместе с деинсталлятором (проверено на живой машине; данные в
`Roaming` при этом целы, но саму 2.2 пришлось ставить заново из релиза).
Менять `productName` обратно нельзя.

Установщик: NSIS, `installMode: currentUser` — ставится **без прав
администратора**, в `%LOCALAPPDATA%`. MSI не собираем: он осмысленен только для
раскатки по GPO и требует фичу Windows VBSCRIPT.

## 4. Выпуск релиза

1. Поднять версию **в двух местах**: `apps/desktop/src-tauri/tauri.conf.json`
   (`version`) и `apps/desktop/src-tauri/Cargo.toml` (`package.version`).
2. Закоммитить и поставить тег из ветки `v3.0`:

```bash
git tag app-v3.0.0
git push origin app-v3.0.0
```

3. `.github/workflows/desktop-release.yml` соберёт три артефакта — Windows,
   macOS ARM, macOS Intel — и создаст **черновик** релиза с `latest.json`.
4. Проверить артефакты, опубликовать релиз.

### Секреты репозитория (заводит владелец)

| Секрет | Что кладём |
|---|---|
| `TAURI_SIGNING_PRIVATE_KEY` | содержимое приватного ключа целиком |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | пустая строка (ключ выпущен без пароля) |

⚠️ Приватный ключ в дерево проекта не попадает **ни на минуту**: репозиторий
публичный. Хранение — GitHub Actions Secrets плюс личная копия в Vaultwarden
(`pass.alex-pronin.ru`). Потеря ключа означает, что установленные приложения
больше не примут ни одного обновления: подпись перестанет сходиться.

Публичный ключ лежит в `tauri.conf.json` (`plugins.updater.pubkey`) — его
коммитить безопасно.

## 5. Что сказать пользователю при установке

### Windows

Файл `UTMka_3.0.0_x64-setup.exe`. Права администратора не нужны.

При первом запуске SmartScreen покажет «Windows защитила ваш компьютер» —
приложение не подписано сертификатом Authenticode. Нажать «Подробнее» →
«Выполнить в любом случае». Это тот же порядок, что был у 2.2.1: сертификат не
покупали намеренно (OV держит предупреждение, пока копится репутация, EV стоит
заметно дороже — решение владельца, ARCHITECTURE §11).

### macOS

**Два разных файла — берите под свой процессор:**

| Процессор | Файл |
|---|---|
| Apple Silicon (M1, M2, M3, M4) | `UTMka_3.0.0_aarch64.dmg` |
| Intel | `UTMka_3.0.0_x64.dmg` |

Посмотреть свой: меню Apple → «Об этом Mac».

Приложение **не подписано и не нотаризовано** — платного Apple Developer
Program ($99/год) у проекта нет, mac-сборка 2.2.1 раздавалась точно так же.
Поэтому первый запуск — не двойным кликом:

1. перетащить UTMka в «Программы»;
2. **правой кнопкой** (или Ctrl+клик) по значку → **«Открыть»**;
3. в окне с предупреждением ещё раз **«Открыть»**.

Дальше приложение открывается как обычное. Двойной клик в первый раз даст
отказ Gatekeeper — это ожидаемо для любого неподписанного приложения, а не
признак поломки.

Альтернатива для тех, кому так спокойнее: собрать у себя из исходников —
`npm ci && cd apps/desktop && npx tauri build`.

## 6. Данные пользователя

| Что | Где |
|---|---|
| Программа 3.0 | `%LOCALAPPDATA%\UTMka 3.0\` |
| Программа 2.2 | `C:\Program Files\UTMka\` — **не трогаем** |
| База 3.0 | `%APPDATA%\UTMka\3.0\utmka.db` (macOS: `~/Library/Application Support/UTMka/3.0/`) |
| База 2.2 | `%APPDATA%\UTMka\databases\utmka.db` — **только читаем** |
| Настройки интерфейса | `localStorage` вебвью (тема, режимы, вид списков) |

Обе версии стоят рядом и не мешают друг другу: 3.0 при первом запуске
предлагает перенести историю и шаблоны, открывая файл 2.2 в режиме чтения.
Отметка о переносе — в таблице `meta`, поэтому второй раз предложение
не появится.

Бэкап — копией файла `utmka.db`. 🪤 При включённом WAL рядом лежат `-wal` и
`-shm`: копировать надо при закрытом приложении, иначе копия окажется неполной.
