## Что делаем сейчас: RU/EN

Последняя незакрытая функция паритета с 2.2. Объём честный: ~360 строк с
кириллицей в apps/web плюс тексты в ядре. Делать одним заходом, не «между
делом» — половина переведённого интерфейса хуже непереведённого.

### Решение по архитектуре (принять, не изобретать заново)

1. **Без локали в URL.** Никаких `/[locale]/` сегментов: инструмент индексируется
   по-русски, а английский нужен интерфейсу, а не поиску. Язык — в localStorage
   (`utmka.settings.v1`, там уже тема и вид списков), тумблер рядом с темой
   в шапке. Ровно как было в 2.2 (`lang-toggle`).
2. **Тексты замечаний остаются в ядре.** Правило CLAUDE.md («формулировки нужны
   форме, маскоту, разбору и пакету — должны совпадать слово в слово») не
   отменяется. Значит в ядре появляется словарь по `IssueCode`, а функции
   принимают локаль: `validateValue(field, value, locale)`,
   `validateDraft(draft, locale)`. Дефолт `'ru'` — тогда 141 существующий тест
   не переписывается.
3. **Где ещё русский в ядре:** `hints.ts` (типовые значения и когда их брать),
   `presets.ts` (title/hint/explain/caveat восьми площадок), `dictionary.ts`.
   Тот же приём: словарь + параметр локали с русским дефолтом.
4. **В вебе** — свой `lib/i18n.ts`: словарь `ru`/`en`, хук `useT()`, чтение
   языка через `useSyncExternalStore` (⚠️ снапшот кэшировать по raw-строке,
   иначе бесконечный ре-рендер — граблю ловили дважды).
5. **Метаданные страниц** (`generateMetadata`, OG, JSON-LD) остаются русскими:
   поисковая аудитория русская, плодить hreflang ради тумблера незачем.

### Порядок работы

1. Ядро: словари + параметр локали, тесты на английские тексты. `npm test`.
2. `lib/i18n.ts` + тумблер языка в шапке (иконка своя, из PixelIcon; сторонние
   icon-библиотеки в проект не тянем).
3. Экраны по одному, начиная с каркаса (DeviceFrame, статус-бар, маскот),
   дальше генератор → пакет → разбор → история → шаблоны → фраза → помощник →
   обучение → помощь. После каждого — `npm run type-check` и `eslint .`.
4. Проверить глазами обе локали через Playwright, потом деплой.

🪤 Грабли этого проекта, на которых уже спотыкались:
- линтер `react-hooks` запрещает setState в теле эффекта и чтение ref в рендере;
  правильный путь — выводить значение из стора либо задавать начальное состояние
  через `key` или ленивый инициализатор;
- `PixelIcon` без размера растягивается на весь флекс-контейнер (дефолт задан,
  но помни при новых иконках);
- элемент с `id="ym"` затирает `window.ym` — таких id в скриптах не давать.
