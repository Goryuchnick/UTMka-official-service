# UTMka 3.0 — бриф на редизайн и веб-версию

> **Что это:** задание на обновление визуала UTMka и проектирование трёх оболочек одного продукта.
> Отдавать в дизайн-сессию (Claude Design) целиком, одним промптом.
>
> **Статус:** черновик v1, 2026-08-08. Развилки, которые ждут ответа владельца, помечены ❓.

---

## 1. Что за продукт

**UTMka** — конструктор UTM-меток для маркетологов и владельцев бизнеса. Существует с 2.x как
десктопное приложение (Windows/macOS, раздаётся через GitHub Releases).

**Что умеет сейчас** (4 рабочих экрана):

| Экран | Задача |
|---|---|
| Генератор | Собрать корректную UTM-ссылку из полей source / medium / campaign / content / term |
| Сокращатель | Укоротить готовую ссылку |
| Сохранение шаблона | Запомнить набор меток под именем |
| Шаблоны | Список сохранённых, повторное применение, история кампаний, импорт/экспорт |

**Новая роль продукта (решение 2026-08-08): это лид-магнит, не бизнес.**
Платных тарифов не будет. Задача — приводить трафик, показывать уровень автора и держать
SEO-присутствие. Из этого следуют дизайн-требования: инструмент должен выглядеть **дороже,
чем бесплатные аналоги**, и быть узнаваемо «работой Александра Пронина».

## 2. Три оболочки, один продукт

| Оболочка | Что это | Аутентификация | Хранение |
|---|---|---|---|
| **Веб (основная)** | Полноценный инструмент в браузере | Кодовая фраза (паттерн курса Prompt.exe), **без email и паролей** | Supabase |
| **Десктоп** | Нативное приложение Windows/macOS, Tauri (Rust) | Не нужна — локальный пользователь | Локальный SQLite |
| **Лендинг** | Страница-описание на основном сайте | — | — |

**Ключевое требование к дизайну:** веб и десктоп используют **одну и ту же вёрстку**.
Различается только слой данных (Supabase против локального SQLite) — интерфейс идентичен.
Дизайнить нужно один раз, с учётом того, что макет поедет в обе оболочки.

Следствия для макета:
- Никаких браузерных допущений в UI (нет «поделиться ссылкой на страницу», нет адресной строки как части опыта).
- Окно десктопа — от 900×600. Компоновка должна выживать в этом размере.
- Всё, что зависит от сети (кодовая фраза, синхронизация), — в отдельном, **опциональном** блоке,
  который в десктопе просто не отображается.

## 3. Требования к визуалу

### 3.1 Эстетика — ✅ решено 2026-08-08

**Эстетика «ПРОНИН-ОС»**, конкретно:

- **База** — текущая главная сайта alex-pronin.ru (device-shell, амбер-CRT, PixelIcon).
- **Светлая тема** — берётся из курса promptexe, не изобретается заново.
- **Маскот** (пиксельный Александр) присутствует внутри инструмента, **со своими текстами** —
  не копия реплик с сайта и не копия курса. Голос: тот же характер, но роль другая — здесь он
  помощник по меткам, а не проводник по курсу.

Маскот — не украшение, а носитель функции: он же лицо ассистента (§3.5).

### 3.2 Обязательное

- **Светлая и тёмная темы** — обе, как сейчас. Тёмная — основная.
- **Мобильная раскладка для веба** — маркетолог собирает метку с телефона чаще, чем кажется.
  Это не «адаптив ужатием», а отдельная логика: генератор в первом экране, шаблоны — во втором.
- **Копирование результата — главное действие экрана.** Сейчас это рядовая кнопка. Должно быть
  очевидной, крупной, с явной обратной связью («скопировано»).
- **Валидация в момент ввода**, а не после. Заглавные буквы в source, пробелы, кириллица,
  дубли параметров — подсвечивать сразу с объяснением, почему это сломает отчёт.
- **Уважение `prefers-reduced-motion`** — анимации отключаемы.

### 3.3 Что улучшить содержательно (не только перекрасить)

1. **Справочник значений.** Главная боль UTM — зоопарк `facebook` / `Facebook` / `fb` / `fb_ads`
   внутри одной команды, из-за которого рассыпаются отчёты. Нужен видимый словарь допустимых
   значений source/medium с автодополнением и предупреждением «такого значения вы раньше не
   использовали — точно новое?». Это то, что отличает продукт от десятка бесплатных генераторов.
2. **Пакетный режим.** Собрать 20 ссылок под 20 площадок за один заход, таблицей, с выгрузкой
   в CSV. Сейчас — по одной.
3. **Разбор чужой ссылки.** Вставил URL с метками — увидел разбор по параметрам и список ошибок.
   Отличный вход для новичка и повод поделиться ссылкой на инструмент.
4. **Пресеты площадок.** Готовые наборы для Яндекс.Директ, ВКонтакте, Telegram Ads, email-рассылок —
   с правильными динамическими подстановками (`{keyword}`, `{campaign_id}` и т.п.), которые
   новички почти всегда пишут неверно.

### 3.5 Ассистент внутри инструмента — в проработку

Решение 2026-08-08: у маскота есть окно ассистента. Это одновременно фича продукта и **витрина
основного навыка автора** (внедрение ИИ) — то есть двойная работа на лид-магнит.

Что ассистент делает — кандидаты, нужно выбрать 2–3 на v3.0:

| Сценарий | Ценность | Сложность |
|---|---|---|
| **Разбор вставленной ссылки** — «что здесь не так и почему рассыплется отчёт» | высокая, самый понятный вход | низкая |
| **Пакет меток из брифа** — вставил текст кампании («запускаем на Директ, ВК и рассылку») → получил готовый набор ссылок | высокая, экономит реальное время | средняя |
| **Проверка на конфликт со справочником** — «вы раньше писали `vk`, сейчас `vkontakte` — свести?» | высокая, ядро продукта | низкая (без LLM, правилами) |
| Объяснение параметров новичку | средняя | низкая |

**Требования к окну ассистента в макете:**
- Не модальное поверх работы — маркетолог должен видеть форму и ответ одновременно.
- Ассистент опционален: инструмент полностью работает без него (в десктопе его может не быть вовсе).
- Состояния: пусто/ждёт, думает, ответ, ошибка сети, **лимит исчерпан**.

⚠️ **Экономика:** сервис бесплатный, а LLM-вызовы платит автор. Обязателен видимый лимит
(например, N обращений в сутки на кодовую фразу) и деградация без драмы: лимит кончился —
инструмент работает дальше, просто без подсказок. Провайдер — routerai (уже используется в проектах).

### 3.4 Чего не делать

- Не тащить платные тарифы, апселлы, счётчики лимитов — продукт бесплатный целиком.
- Не собирать персональные данные. Кодовая фраза именно затем, чтобы не было email и 152-ФЗ-обвязки.
- Не делать регистрацию обязательной: инструмент обязан работать **сразу**, без входа.
  Кодовая фраза нужна только чтобы сохранить шаблоны и подобрать их с другого устройства.

## 4. Что нужно на выходе дизайн-сессии

1. Экраны в тёмной теме: генератор, пакетный режим, шаблоны/справочник, разбор ссылки,
   экран кодовой фразы, пустое состояние.
2. Мобильная раскладка генератора и шаблонов.
3. Светлая тема — на генераторе, для проверки, что палитра переживает инверсию.
4. Токены (цвета, типографика, отступы, радиусы) — отдельным блоком, чтобы перенести в код 1:1.
5. Состояния: ошибка валидации, «скопировано», загрузка, конфликт значения со справочником.

**Перенос в код — строго 1:1** (разметка и классы прототипа, без переизобретения своими
компонентами). Правило зафиксировано по итогам редизайна pronin-alex.

## 5. Решения и открытые вопросы

### ✅ Решено 2026-08-08

| Вопрос | Решение |
|---|---|
| **Домен** | **Лендинг — `alex-pronin.ru/utmka`** (подпапка, работает на SEO основного домена). **Сам сервис — `utmka.alex-pronin.ru`**: там несколько разделов (генератор, шаблоны, история, админка), это самостоятельное приложение, а не страница. SEO-задачу несёт лендинг, инструмент несёт продуктовую |
| **Эстетика** | ПРОНИН-ОС: текущая главная + светлая тема из курса promptexe + маскот со своими текстами (§3.1) |
| **Ассистент** | Да, окно ассистента с маскотом. Сценарии — в проработке (§3.5) |
| **Порядок** | **Веб первым.** Десктоп на Tauri — после того, как дизайн устоится на живых пользователях |

⚠️ **Следствие развилки доменов для SEO:** раз инструмент вынесен на субдомен, лендинг обязан
нести на себе весь поисковый вес — то есть это не заглушка с кнопкой, а полноценная страница:
что такое UTM, частые ошибки, примеры для Директа и ВК, FAQ. Иначе SEO-задача не решается вообще.
