# UTMka — ассистент: что он делает и на чём работает

> Черновик от 2026-08-08. Отвечает на два вопроса владельца: **что вообще прикрутить**
> и **как это будет работать на десктопе** (локальная модель? скрипты?).
> Дополняет [DESIGN-BRIEF.md](DESIGN-BRIEF.md) §3.5.

---

## 1. Главный вывод: 80% пользы не требует нейросети

Разбор реальных болей UTM показывает, что почти всё — **детерминированные правила**, а не задачи
для языковой модели. Это отличная новость: правила работают офлайн, мгновенно, бесплатно,
одинаково в вебе и в десктопе, и — в отличие от LLM — **никогда не врут**.

Поэтому ассистент строится тремя слоями, и первый несёт основную ценность.

| Слой | Чем работает | Где доступен | Стоимость |
|---|---|---|---|
| **0. Правила** | Обычный TypeScript-код | Веб **и десктоп**, офлайн | 0 |
| **1. Сеть** | Запросы наружу (проверка ссылок) | Веб и десктоп при наличии сети | 0 |
| **2. LLM** | routerai | **Только веб**, опционально, с лимитом | платно, лимитируем |

Локальная модель на ПК — **не рассматриваем**: 2–4 ГБ весов ради задачи, которая решается
регулярным выражением, убивает главное преимущество Tauri (приложение на 10 МБ).

## 2. Слой 0 — правила. Ядро продукта

Всё ниже реализуется кодом, работает в обеих оболочках, не требует сети.

### 2.1 Валидация в момент ввода

Проверки, каждая с человеческим объяснением последствия — не «ошибка», а «что сломается в отчёте»:

| Проверка | Почему это важно |
|---|---|
| **Регистр** | `Facebook` и `facebook` — два разных источника в отчёте. Классика расщепления данных |
| **Пробелы** | `back to school` ломает URL, отчёт получает обрезки |
| **Кириллица** | Метрика и GA4 плохо обрабатывают кириллицу в URL — URL задуман под латиницу |
| **Спецсимволы** | `&`, `?`, `#` внутри значения рвут разбор параметров |
| **Дубль параметра** | Два `utm_source` в одной ссылке — поведение непредсказуемо |
| **Длина URL** | Слишком длинные ссылки обрезаются в почтовых клиентах и мессенджерах |
| **Семантика** | `utm_medium=organic` на платном трафике — метка есть, а данные врут. Ловушка, которую валидаторы не ловят, а мы поймаем |

### 2.2 Нормализация одним нажатием

«Привести в порядок»: нижний регистр, пробелы → `_`, транслит кириллицы, обрезка хвостовых
пробелов, удаление пустых параметров. Показывать **до/после**, а не молча переписывать.

### 2.3 Справочник значений — главное отличие от бесплатных генераторов

Это то, ради чего инструментом будут пользоваться повторно.

- Хранит все использованные значения `source` / `medium` / `campaign`.
- Автодополнение при вводе.
- **Предупреждение о новом значении:** «`vkontakte` вы раньше не использовали, но есть `vk`.
  Это то же самое?» → предложение свести.
- **Детектор расщепления:** периодически показывает «у вас 3 написания одного источника:
  `telegram`, `tg`, `messenger` — отчёты по ним не сойдутся».
- Экспорт справочника — чтобы команда пользовалась одним словарём.

Аналог из мира дорогих инструментов: платные UTM-платформы продают именно это —
принудительные соглашения об именовании и общую библиотеку кампаний для команды.
У нас это будет бесплатно.

### 2.4 Разбор чужой ссылки

Вставил URL → таблица параметров + список найденных проблем + кнопка «починить».
Лучший вход для новичка и естественный повод поделиться инструментом.

### 2.5 Пакетный режим

Таблица: строки — площадки, столбцы — параметры. Заполнил один раз, получил 20 ссылок.
Импорт списка площадок и экспорт в CSV / буфер.

### 2.6 Пресеты площадок с динамическими подстановками

Здесь новички ошибаются чаще всего, а цена ошибки — потерянная семантика за весь период.

- **Яндекс.Директ:** `{keyword}`, `{campaign_id}`, `{ad_id}`, `{source_type}`, `{device_type}`,
  `{region_name}` — с пояснением, что каждый вернёт. Особо: `utm_term={keyword}` нужен, чтобы
  вообще видеть, по каким запросам шли показы.
- **ВКонтакте:** канон `utm_source=vk`, `utm_medium=social` (или `cpc` для платного) + подстановки кабинета.
- **Telegram Ads, email-рассылки, QR-коды офлайн** — свои наборы.

Пресет должен объяснять **разницу между площадкой и типом трафика** — почему `vk` это source,
а `social`/`cpc` это medium. На этом путается большинство.

### 2.7 Проверка редиректов ⚠️ требует сети

Метки часто теряются на редиректах и не попадают в первый входной URL. Кнопка «проверить
ссылку»: пройти цепочку переадресаций и показать, дожили ли параметры до конечной страницы.
В десктопе работает при наличии интернета, офлайн — просто недоступна.

## 3. Слой 2 — LLM. Только там, где правила бессильны

Языковая модель нужна ровно для одного класса задач: **свободный человеческий текст → структура**.

| Сценарий | Что делает | Приоритет |
|---|---|---|
| **Бриф → пакет меток** | «Запускаем осенний набор на Директ, ВК и рассылку» → готовый набор ссылок с осмысленными `campaign` | ⭐ высокий |
| **Имя кампании** | Предложить `campaign` в принятом в справочнике стиле по описанию | средний |
| **Объяснение новичку** | «Почему medium=organic здесь неправильно» человеческими словами, а не текстом ошибки | средний |
| Разбор кривой ссылки словами | Дублирует §2.4, но мягче для непонимающего | низкий |

**Требования:**
- Только веб. В десктопе окно ассистента не показывается вовсе (либо помечено «нужен интернет»).
- Видимый лимит на кодовую фразу. Кончился — инструмент работает дальше, без подсказок, без драмы.
- Ответ LLM **всегда прогоняется через слой 0** перед выдачей: модель может предложить значение
  с пробелом или кириллицей. Правила — последняя инстанция, не модель.

## 4. Ответ на вопрос «как на ПК»

**Никакой локальной модели.** Схема такая:

```
Десктоп (Tauri)          Веб
├─ слой 0: правила  ✅   ├─ слой 0: правила  ✅  (тот же код)
├─ слой 1: сеть     ✅   ├─ слой 1: сеть     ✅
└─ слой 2: LLM      ✖    └─ слой 2: LLM      ✅ (лимит)
```

Слои 0 и 1 — общий TypeScript-модуль, компилируется в обе оболочки. Это и есть тот самый
«ассистент на скриптах», про который спрашивал владелец: он делает почти всё, что нужно,
и делает это надёжнее модели.

Маскот при этом остаётся в обеих оболочках — он комментирует **результаты правил**
(«тут регистр разъедется», «у вас три написания Telegram»), и для этого нейросеть не нужна.
Пользователь видит одинаково живого помощника, просто в вебе он умеет ещё и понимать
свободный текст.

## 5. Что ещё можно прикрутить — идеи на потом

| Идея | Ценность | Сложность |
|---|---|---|
| **QR-код на готовую ссылку** | офлайн-реклама, листовки, витрины — маркетологу нужно постоянно | низкая |
| **Проверка, долетела ли метка** — по API Метрики показать, появился ли источник в отчётах | закрывает круг: собрал → проверил, что работает | высокая (OAuth) |
| **Импорт кампаний из Директа** | автозаполнение справочника реальными названиями | высокая |
| **Браузерное расширение** | собрать метку прямо на странице, куда ведёшь трафик | средняя |
| **Совместный справочник команды** | несколько кодовых фраз — один словарь | средняя |
| **История с поиском и тегами** | найти «ту ссылку с прошлого сентября» | низкая |
| **Шаблон под клиента/проект** | агентствам — разделение по клиентам | низкая |
