## Что случилось 25 августа

21.08 в поиск вошли все 11 адресов. 25.08 **шесть посадочных вышли обратно**
со статусом `LOW_QUALITY` — «недостаточно качественная страница»:

```
/dzen  /email  /qr  /telegram  /tilda  /vk
```

Остались `/`, `/help`, `/parse`, `/batch`, `/yandex-direct`.

Объём текста тут ни при чём — это видно по числам:

| Страница | Текста роботу | В поиске |
|---|---|---|
| `/help` | 5862 симв. | да |
| `/` | 3658 | да |
| `/tilda` | 3273 | **нет** |
| `/vk` | 3234 | **нет** |
| `/yandex-direct` | 3260 | да |
| `/batch` | 469 | да |
| `/parse` | 427 | да |

`/parse` и `/batch` отдают роботу по четыре сотни символов и в поиске остались,
а посадочные с тремя тысячами — вылетели. Значит дело не в объёме, а в том, что
шесть страниц выглядят **одной серией по шаблону**: одинаковая структура,
одинаковый генератор, отличия в словах про площадку. На молодом домене без
внешнего спроса и ссылок такая серия схлопывается — Яндекс оставляет по одному
представителю типа (`/yandex-direct`) и режет остальные.

Это не приговор: `LOW_QUALITY` снимается, когда у страницы появляется
собственная ценность и хоть какой-то спрос.

## Порядок работ

**1. Дать каждой посадочной то, чего нет у соседей.** Не абзац текста — блок,
за которым и приходят:

* таблица подстановок именно этой площадки (у Директа `{campaign_id}`, у VK
  `{{ad_plan_id}}`, у Google Ads `{campaignid}`) — ядро уже знает их все,
  `packages/core/src/macros.ts`;
* три-четыре типичные ошибки площадки с тем, что от них ломается в отчёте
  (тексты живут в `validate.ts`, копировать не надо);
* готовый пример ссылки, разобранный по частям;
* что площадка режет или переписывает в ссылке сама.

`/tilda` — первый кандидат: по ней уже есть показы и позиция 3.

**2. Написать текст `/parse` и `/batch`.** Сейчас робот видит на них четыре
сотни символов — ранжироваться нечем. Главную так уже чинили 14.08 (было 291
символов и заглушка «Загружаю генератор…»), тем же приёмом.

**3. Внешние сигналы.** С `alex-pronin.ru/tools/utmka` ведёт ровно одна ссылка —
на корень субдомена. Посадочные не упомянуты нигде. Ссылки на конкретные
страницы из статей блога и с самого лендинга дают Яндексу повод пересмотреть
`LOW_QUALITY`, а Google — вообще заметить сайт.

**4. Переобход после правок.** Через API Вебмастера, квота ~150 адресов в
сутки:

```bash
curl -X POST ".../hosts/$HOST_ID/recrawl/queue" -H "$AUTH" \
     -H "Content-Type: application/json" -d '{"url": "https://utmka.alex-pronin.ru/tilda"}'
```

Google переиндексацию по API не отдаёт (Indexing API — только вакансии):
свежий sitemap плюс «Проверка URL → Запросить индексирование» руками.

**5. Две настройки руками в Вебмастере.** API их не отдаёт, а в диагностике они
висят:

* Индексирование → **Обход по счётчикам Метрики** (счётчик 111529339) — робот
  начнёт узнавать о страницах из трафика;
* Информация о сайте → **Региональность**.

Третья рекомендация — «сайта нет в Яндекс.Справочнике» — не наш случай: у
онлайн-инструмента нет адреса.

## Чего не делаем

* **Не плодим посадочные под новые площадки, пока не вылечены эти шесть.**
  Добавить седьмую страницу той же серии — значит усилить ровно тот признак,
  из-за которого её выкинули.
* **Не гоним трафик рекламой ради SEO.** Поведенческие на молодом сайте так не
  строятся, а бюджет уходит.
* Не трогаем `robots.txt` и `sitemap.xml` — они в порядке: карта отдаёт 11
  адресов, личные разделы закрыты, `index, follow` на месте.
