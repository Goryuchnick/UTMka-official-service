## Правила ядра (`packages/core`)

Ядро едет и в веб, и в будущий десктоп на Tauri, поэтому:

- **ноль зависимостей, ноль сети, ноль DOM.** Всё внешнее принимается параметром
  (fetcher в `redirect.ts`, репозиторий в `repository.ts`);
- тексты замечаний живут в `validate.ts`, а не в интерфейсе — одни и те же формулировки
  нужны форме, маскоту, разбору и пакетному режиму;
- каждое замечание объясняет **что сломается в отчёте**, а не «неверный формат»;
- любое изменение поведения — с тестом. `npm test` в корне гоняет все воркспейсы.

```bash
npm test                       # тесты всех пакетов
npm run type-check             # tsc --noEmit по всем пакетам
cd packages/core && npx vitest  # watch-режим по ядру
```

### Что нельзя сломать

- **Плейсхолдеры площадок не кодируются.** `utm_term={keyword}` обязан доехать до Директа
  буквально; `%7Bkeyword%7D` ломает подстановку. Проверяется тестами в `test/build.test.ts`.
- **Паритет с 2.2** по сборке ссылки: схема дописывается, чужие параметры сохраняются,
  пустые UTM игнорируются, пробел кодируется плюсом.
- **Предохранители SSRF** в `redirect.ts` проверяются на каждом хопе, а не только на первом.

## Десктоп 2.2 (`legacy/desktop-2.2/`)

Работает как раньше, пути внутри относительные:

```bash
cd legacy/desktop-2.2
python run_desktop.py --dev     # Flask в браузере
python run_desktop.py           # окно PyWebView
python rebuild.py               # сборка dist/UTMka/UTMka.exe
```

Версия — `src/core/version.py` (единственный источник). Логика UTM — `src/core/services.py`,
это спецификация поведения для ядра 3.0. Экраны и состояния — `frontend/`.
