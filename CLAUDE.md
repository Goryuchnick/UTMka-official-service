## Что это за репозиторий

**UTMka** — конструктор UTM-меток. Сейчас в репозитории два поколения продукта:

| Что | Где | Состояние |
|---|---|---|
| **3.0** — веб + десктоп на общих экранах и правилах | `packages/`, `apps/` | в работе, ветка `v3.0` |
| **2.2.1** — десктоп на Flask + PyWebView | `legacy/desktop-2.2/` | **заморожен**, правки только критические |

⚠️ **Работа над 3.0 идёт в ветке `v3.0`.** В `main` лежит выпущенный десктоп 2.2.1,
туда ничего не коммитим до слияния.

**Источник правды по архитектуре — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).**
Все решения фиксируются там, в журнале решений (§11). Рядом: [docs/DESIGN-BRIEF.md](docs/DESIGN-BRIEF.md)

## Раскладка

```
packages/core/        @utmka/core — слой правил: валидация, нормализация, сборка,
                      разбор, справочник, пресеты, пакет, редиректы, форматы
                      обмена, правила хранения, контракт оболочки. Чистый TS.
packages/ui/          @utmka/ui — экраны: 38 компонентов + globals.css (3118 строк).
                      Ни fetch, ни next/*, ни invoke: внешний мир приходит
                      через алиас `#shell`
apps/web/             Next.js-приложение (utmka.alex-pronin.ru) — ШАГ 3
apps/desktop/         Tauri + Vite — ШАГ 7. src-tauri/: SQLite, сеть, импорт 2.2
legacy/desktop-2.2/   замороженный Python-десктоп
docs/                 архитектура, брифы, скриншоты 2.2
```

**Направление зависимостей:** `core ← ui ← оболочки`. Ядро не знает ни React,
ни сети; экраны не знают, где они выполняются.

### Алиас `#shell` — граница оболочки

Экраны импортируют `backend`, `saveFile`, `useNav`, `useNavParams`, `NavLink`
из `../shell`, а он реэкспортирует алиас `#shell`. Каждое приложение направляет
алиас в свою реализацию:

| Приложение | `#shell` | Задаётся |
|---|---|---|
| `apps/web` | `lib/shell.tsx` (fetch + next/navigation) | `tsconfig.paths` + `turbopack.resolveAlias` |
| `apps/desktop` | `src/lib/shell.tsx` (invoke + react-router) | `tsconfig.paths` + `resolve.alias` в `vite.config.ts` |

Новую возможность оболочки заводить **в контракте ядра** (`backend.ts`), потом
реализовывать в обеих — иначе экран, написанный под одну, молча ломается в другой.

## Десктоп 3.0 (`apps/desktop/`)

```bash
cd apps/desktop
npx tauri dev            # окно + Vite на 1420
npx tauri build          # NSIS-установщик (нужен ключ апдейтера в env)
cd src-tauri && cargo test   # 30 тестов: хранилище, сеть, импорт 2.2
```

Сборка требует Rust (`stable-msvc`). Переменные `CARGO_HOME`, `RUSTUP_HOME`,
`CARGO_TARGET_DIR` уведены на `D:\rust\*` — `target/` у Tauri разрастается до
десятков гигабайт.

Подробности релиза — [docs/DESKTOP-BUILD.md](docs/DESKTOP-BUILD.md).

### Что нельзя сломать в десктопе

- **Справочник наполняет `history_add`**, отдельной ручки нет. Реализация,
  которая просто пишет строку, не упадёт и ничего не скажет — справочник просто
  останется пустым.
- **Уникальность имени шаблона держит колонка `name_key`**, а не индекс по
  `lower(name)`: встроенный `lower()` в SQLite не понижает регистр кириллицы,
  и «Осень» с «ОСЕНЬ» разъехались бы на два шаблона.
- **База 2.2 открывается только на чтение.** 2.2.1 остаётся установленной.
- **Цепочку редиректов ведёт ядро**, Rust делает один хоп (`net_hop`).
  Переписать обход на Rust — значит завести второй экземпляр логики.

## Правила ядра (`packages/core`)

Ядро едет и в веб, и в будущий десктоп на Tauri, поэтому:

- **ноль зависимостей, ноль сети, ноль DOM.** Всё внешнее принимается параметром
  (fetcher в `redirect.ts`, репозиторий в `repository.ts`);
- тексты замечаний живут в `validate.ts`, а не в интерфейсе — одни и те же формулировки
  нужны форме, маскоту, разбору и пакетному режиму;
- каждое замечание объясняет **что сломается в отчёте**, а не «неверный формат»;
- любое изменение поведения — с тестом. `npm test` в корне гоняет все воркспейсы.

```bash
npm test                       # тесты всех пакетов
npm run type-check             # tsc --noEmit по всем пакетам
cd packages/core && npx vitest  # watch-режим по ядру
```

### Что нельзя сломать

- **Плейсхолдеры площадок не кодируются.** `utm_term={keyword}` обязан доехать до Директа
  буквально; `%7Bkeyword%7D` ломает подстановку. Проверяется тестами в `test/build.test.ts`.
- **Паритет с 2.2** по сборке ссылки: схема дописывается, чужие параметры сохраняются,
  пустые UTM игнорируются, пробел кодируется плюсом.
- **Предохранители SSRF** в `redirect.ts` проверяются на каждом хопе, а не только на первом.

## Десктоп 2.2 (`legacy/desktop-2.2/`)

Работает как раньше, пути внутри относительные:

```bash
cd legacy/desktop-2.2
python run_desktop.py --dev     # Flask в браузере
python run_desktop.py           # окно PyWebView
python rebuild.py               # сборка dist/UTMka/UTMka.exe
```

Версия — `src/core/version.py` (единственный источник). Логика UTM — `src/core/services.py`,
это спецификация поведения для ядра 3.0. Экраны и состояния — `frontend/`.
